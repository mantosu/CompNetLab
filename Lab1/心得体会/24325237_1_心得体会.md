## 本人承担的工作

我负责 C++（Winsock）版本的 UDP 客户端与服务器端程序（`udp_client.cpp`、`udp_server.cpp`）的编写，包括 `WSAStartup`/`WSACleanup` 初始化、`socket(AF_INET, SOCK_DGRAM)` 创建数据报套接字、`bind` 绑定、`sendto`/`recvfrom` 收发数据，以及用 `setsockopt` 设置 `SO_RCVTIMEO` 接收超时来判定发送结束；同时负责仓库的 git 管理——初始化仓库、编写 `.gitignore` 忽略编译产物、把 C++ 源码整理进 `cpp/` 目录。

## 遇到的困难及解决方法

我在 C++ 这边遇到的第一个问题是：程序一调用 `socket` 就返回 `SOCKET_ERROR`，错误码是 `WSANOTINITIALISED`。原因是 Windows 下必须先加载 Winsock 库。解决方法是所有 Winsock 调用之前先执行 `WSAStartup(MAKEWORD(2,2), &wsaData)`，程序结束前调用 `WSACleanup()`。

第二个问题是编译链接报错。源码里的 `#pragma comment(lib, "ws2_32.lib")` 只对 MSVC 生效，我用的是 MinGW g++，必须手动加 `-lws2_32` 才能链接成功。

第三个问题是地址结构的字节序：端口和 IP 需要转成网络字节序，否则收发会错乱。解决方法是端口用 `htons()`、IP 用 `inet_addr()`/`htonl()` 转换。另外我一度把编译出的 exe 提交进了仓库，后来补了 `.gitignore` 忽略 `*.exe` 等产物并移除了已提交的可执行文件。

## 体会与总结

通过 C++ 版本，我把 Winsock 编程的完整流程走了一遍：`WSAStartup → socket → bind → sendto/recvfrom → closesocket → WSACleanup`。我理解了 `struct sockaddr_in` 与 `struct sockaddr` 都是 16 字节、可以通过强制类型转换互换——前者用于赋值，后者用于函数参数，这个细节在实际编码时很容易被忽略。用 `SO_RCVTIMEO` 让 `recvfrom` 超时返回，也让我认识到 UDP 无连接带来的"没有结束标志"问题必须在应用层解决。这次实验让我对网络字节序、地址结构这些底层概念有了实实在在的掌握。
