## 一、我承担的工作

这次实验我负责 R2 和 PC2 的配置，同时执笔小组实验报告。

PC2 的实验网卡配成 `192.168.3.22/24`，网关 `192.168.3.1`。配完我用 `ipconfig /all` 确认地址落在实验网卡上，没有配到 `172.16.6.x` 那块校园网网卡。R2 这边，实际接口是 `GE0/0/1` 接 R1、`GE0/0/0` 接 PC2，不是手册写的 `GE0/0/6`、`GE0/0/7`。我在 `GE0/0/1` 上配 `192.168.2.2/24`，在 `GE0/0/0` 上配 `192.168.3.1/24`，然后进 `ospf 1` 的 `area 0`，把 `192.168.2.0/24` 和 `192.168.3.0/24` 发布出去。

配置过程中我用 `display ip interface brief` 看接口和 IP，用 `display ospf peer` 看邻居，用 `display ospf interface` 确认 OSPF 跑在哪个接口上，最后用 `display ip routing-table` 看有没有 `OSPF` 条目。实验结束后，我负责把大家的截图按步骤收进报告，核对接口名、命令和现象，写成小组报告。

## 二、遇到的困难及解决方法

### 1. R2 配 `192.168.3.1` 提示地址冲突

一开始我按手册在 R2 的 `GE0/0/6` 上配 `192.168.3.1`，设备直接提示地址冲突，命令没下去。我先执行 `display ip interface brief` 和 `display current-configuration`，发现实验三的接口 IP 和静态路由还留着，`192.168.3.1` 之前在 R2 的另一个接口上已经用过。再对着实际接线看，R2 这次用的是 `GE0/0/1` 和 `GE0/0/0`，不是手册写的 `GE0/0/6`、`GE0/0/7`。

把旧 IP 和静态路由清掉，按实际接口重新配，冲突就没了。这件事让我记住：手册上的接口名只是例子，设备型号、插槽不一样，接口编号就可能变。配之前先 `display interface brief` 看一眼，比照着手册猜要靠谱。

### 2. 禁用校园网网卡后 MobaXterm 断连

为了让 PC2 的实验网卡不被校园网默认网关影响，我禁用了校园网网卡。刚禁用，MobaXterm 里 telnet R2 的窗口就断了。
后面我们改成用第三台 PC 保持校园网、专门 telnet；或者保留校园网网卡，加一条精确路由。说到底，实验网和管理网是两条线，不能为了方便测试把管理通道关掉。

在 R2 上执行 `display ospf peer`，只看到一行：

```text
OSPF Process 1 with Router ID 172.16.6.204
```

下面没有邻居表，也没有 `Full`。我一开始以为这行就是邻居信息，后来查 `display ospf interface` 才发现，OSPF 并没有跑在实际互联的接口上。`172.16.6.204` 只是 R2 自动选的 Router ID，不是邻居。

把 `GE0/0/1`、`GE0/0/0` 的 IP 和 `network` 改对之后，邻居才起来，R2 路由表也出现了 `OSPF 192.168.1.0/24`。我也记住了：没有邻居时先看 OSPF 接口，再看 Hello；`display ospf peer` 第一行只是本地进程信息，别把它当邻居。

### 4. `network` 命令报 `Unrecognized command found at '^' position`

在 R2 的 area 视图敲 `network 192.168.2.0 0.0.0.255` 时，设备报：

```text
Error: Unrecognized command found at '^' position.
```

我退出重新进了一遍 `ospf 1` → `area 0`，确认视图是 `[R2-ospf-1-area-0.0.0.0]`，再用英文半角空格逐字敲，命令就过了。复制粘贴时很容易混进全角空格或看不见的字符，华为命令行对这个比较敏感。遇到这个报错，先看视图，再看空格，最后重新逐字输入，比反复改 IP 有用。

### 5. 写报告时接口名和截图对不上

作为执笔人，我还要把全组截图整理进报告。最大的麻烦是手册接口名和实际接口不一致：截图里 R2 用的是 `GE0/0/1`、`GE0/0/0`，手册写的是 `GE0/0/6`、`GE0/0/7`。我得逐张核对 `display ip interface brief` 和路由表，把报告里的接口统一成实际接口，并在报告里说明这个差异。

还有 PC1/PC2 抓包这个细节。一开始我以为 PC 上抓不到 OSPF 包，实际抓下来发现本网段的 Hello 是能看到的，只是看不到 R1—R2 的完整邻接过程。如果只按课本写、不看截图，报告里很容易写错。这让我意识到，写报告不是把截图贴上去就行，得先看懂每一步在做什么。

## 三、体会与总结

这次实验给我印象最深的是排错顺序。以前遇到 ping 不通，容易一上来就怀疑路由协议；这次我按“接口状态 → 接口 IP → OSPF 接口 → 邻居 → 路由表”的顺序查，发现大部分问题都在前面几步：接口配错、IP 配到旧接口、`network` 没生效。把这些基础项确认完，再看 OSPF 邻居和路由表，思路会清楚很多。

我也更深刻地体会到，手册和设备实际输出不是一回事。手册给的是示例，`display interface brief`、`display ip interface brief` 才是设备当前的真实状态。实验三的静态路由没清，也差点让我误以为 OSPF 已经生效；后来看 `Proto` 列，`Static` 和 `OSPF` 分清楚，才知道问题在哪。

作为写报告的人，我的另一个收获是：报告里的每一张截图、每一条命令，自己都要能解释。整理截图时我会顺便回想当时为什么这么配、报错是怎么排掉的，这比单纯把图堆在一起更花时间，但也更能把实验串起来。

## 四、改进建议

- 实验前先清旧配置，至少用 `display current-configuration` 检查一遍，别让上一次实验的静态路由和接口 IP 干扰判断。
- 接口名不要照抄手册，配之前先 `display interface brief`，并把实际接口记在报告里。
- 需要保留 telnet 管理通道时，用第三台 PC 或 `route add`，不要直接禁用校园网网卡。
- 建议显式配置 `router-id`，这次 R2 自动选了 `172.16.6.204`，虽然能用，但 DR/BDR 结果不够直观。
- 截图时顺手把命令、现象和结果记下来，并按统一规则命名，后面写报告会省很多时间。
