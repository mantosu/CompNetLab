## 1. 实验室物理环境

- 实验室共 **27 组**基础实验平台，每组含 **4 台基础网络设备**：
  - 三层交换机 **2 台**：S5720-36PC-E1、S5735-S24T4XE-V2
  - 路由器 **2 台**：AR6140E-9G-2AC、AR2200S
- 每组配 **3 台 PC**（命名为 `D42_xx`）
- 每组通过一个 **8 口交换机**上联核心交换机，用于连接 3 台 PC + 组内 4 台设备
- 校园网交换机：**S5700**；核心 S5700 上联代理服务器（`172.16.0.1/16`）接入校园网
- 为防组间干扰，核心交换机上做了 **组间隔离**

## 2. 组内设备与管理 IP ⭐

所有设备通过**管理端口 IP** 登录管理，命名规律：`172.16.X.20*`

| 设备 | 型号 | 管理 IP（组 X） | 本组（X=6） |
| :--- | :--- | :--- | :--- |
| 交换机 SW1 | S5720-36PC-E1 | `172.16.X.201` | `172.16.6.201` |
| 交换机 SW2 | S5735-S24T4XE-V2 | `172.16.X.202` | `172.16.6.202` |

> X 为组号（1~27），`*` 为设备号（1~4）。
> 例：`telnet 172.16.1.201` 连接第 1 组交换机 SW1。

## 4. 登录设备

设备须用 **telnet 或 SSH** 登录（实验室 PC 是 Win10，无自带 telnet 客户端，已装第三方工具）。

```
telnet 172.16.X.20*        # X=组号 1~27, *=设备号 1~4
Username: user
Password: b402b402         # 密码无回显
```

| 项目 | 值 |
| :--- | :--- |
| 用户名 | `user` |
| 密码 | `b402b402`（输入时无回显） |
| 客户端 | **SecureCRT** 或 **MobaXterm_Personal_22.1**（每台 PC 均已安装） |

**本组（X=6）示例**：`telnet 172.16.6.203` → 登录本组路由器 R1

## 6. 设备端口一览

### 路由器 R1 — AR6140E-9G-2AC

- 9 个千兆以太网路由端口：
  - `GE0`、`GE1`（蓝色标识）— 默认作 **WAN** 路由口，可用
  - `GE2`、`GE3`（黄色标识）— 默认作 **LAN** 口；**若要作三层路由口，需先 `undo portswitch`**
  - `GE4`~`GE7` — 未插模块，**不可用**
  - `GE8` — 管理端口，**实验中不可用**

### 路由器 R2 — AR2200S

- 10 个千兆以太网三层路由端口：
  - `GE4`~`GE8` — **可用**（5 个）
  - `GE0`~`GE3` — 未插模块，**不可用**
  - `GE9` — 管理端口，**实验中不可用**

> ⚠️ **2026 实验 3 实测**：本组 R2 的 `GigabitEthernet0/0/1`、`GigabitEthernet0/0/2` 作为业务口均正常 UP，与上表"GE0~GE3 不可用"的描述不一致。实验室设备存在个体差异，**一律以 `display interface brief` 的实际输出为准**。

### 交换机 SW1 — S5720-36PC-E1

- 28 个千兆以太网端口，其中 **25~28 口为光电两用**
- 4 个万兆光口 — 未插模块，**不可用**
- `MEth0/0/1` — 管理端口，**实验中不可用**

### 交换机 SW2 — S5735-S24T4XE-V2

- **端口命名与其他设备不同**：
  - 24 个千兆口：`GE1/0/1` ~ `GE1/0/24`
  - 4 个万兆口：`10GE1/0/1` ~ `10GE1/0/4`（未插模块，不可用）
- 其中 **23、24 口是管理 vlan999**，**实验中不可用**

> ⚠️ 实验室设备型号不统一，**做实验前务必先 `display interface brief` 查看实际接口**，再按实际情况配置。

## 7. 网线与网卡

- **红色标签网线**（共 4 条）= 各设备的**管理线**，**严禁插拔**
- **黄色标签网线**（3 条）= 连接各 PC **后面板的实验网卡**，分别对应 PC1~PC3，用于实验时连接 PC 与设备接口
- 每台 PC 有 **2 块网卡**：
  1. **校园网网卡** — 连接实验室网络设备（校园网 + 各设备管理端口）
  2. **实验网网卡** — 用于搭建本组的实验网络
- 部分机器还有**无线网卡**

## 8. ⭐ 两种"网段"必须分清（重要）

实验中存在两套完全不同的地址体系，混淆会导致 ping 不通：

| | 管理网（172.16.0.0/16） | 实验网（自定） |
| :--- | :--- | :--- |
| 用途 | PC 登录、配置设备 | 搭建实验拓扑、跑实验 |
| 使用哪块网卡 | 校园网网卡 | 实验网网卡（或 USB 转接网卡） |
| 地址 | PC：`172.16.X.1-3`<br>设备管理口：`172.16.X.20*` | 由学生自行规划 |
| 例子 | `172.16.6.201`（本组 SW1） | ACL 实验中：`192.168.10.0/24`、`10.1.1.0/24` |

**说明**：

- 讲义里的 `192.168.10.*`、`10.1.1.*` 只是**示例网段**，属于"实验网"，可按需替换为其它**私有地址**，只要同网段内不冲突、掩码与网关设置正确即可。
- 路由器业务端口的 IP 就是**它所在实验网段的网关地址**（如 ACL 实验里 `g0/0/2` = `192.168.10.1/24`），不是管理 IP。
- 可用私有地址范围（来自讲义 Chap1）：
  - `10.0.0.0 ~ 10.255.255.255`（10/8，1 个 A 类）
  - `172.16.0.0 ~ 172.31.255.255`（172.16/12，16 个连续 B 类）
  - `192.168.0.0 ~ 192.168.255.255`（192.168/16，256 个连续 C 类）

## 9. 设备配置基础

### 命令视图

| 视图 | 提示符 | 进入方式 | 作用 |
| :--- | :--- | :--- | :--- |
| 用户视图 | `<...>` | 登录后默认 | 基本测试、显示系统信息 |
| 系统视图 | `[...]` | `system-view` | 全局参数配置 |
| 接口视图 | `[R2-GigabitEthernet0/0/1]` | `interface g0/0/1` | 配置接口参数 |
| 线路视图 | `[R2-ui-vty0]` | `user-interface vty 0` | 配置路由器线路参数 |

> 不同视图对应不同命令集，**必须进入相应视图才能执行对应配置命令**。

### 常用操作

```
?                        # 查看当前视图下所有命令
display ?                # 查看 display 后可接的命令
disp?                    # 命令补全提示
interface GigabitEthernet 0/0/1     # 全写
int g0/0/1                          # 简写（需能唯一识别）
sysname sysu                        # 给设备改名
display this                        # 查看当前视图下的配置
display interface brief             # 查看所有接口状态 ⭐ 实验前必做
```

**接口编号规则**：`设备号/板卡号/端口号`，如 `0/0/1`
- 设备号：单台设备通常为 0（本地设备）
- 板卡号：无扩展槽位的固定端口设备通常为 0
- 端口号：该板卡上的物理端口序号，从 1 开始

### 启用 / 禁止接口

```
[Switch]interface gigabitethernet 0/0/2
[Switch-gigabitethernet 0/0/2]shutdown          # 关闭接口
[Switch-gigabitethernet 0/0/2]undo shutdown     # 启用接口
```

- 接口两种状态：**up**（管理状态开启）/ **down**（关闭）
- ⚠️ 实验前用 `display interface brief` 检查所用接口，**必须为 UP 状态**

## 10. 一键清与实验后处理

**一键清**：把本组所有设备的配置恢复为缺省，给下一组学生干净环境。

```
python clear.py x        # x 为组号；clear.py 在 PC 的 MobaXterm 目录下
```

- 实验室每台 PC 已装 **Python 3.10**
- 脚本执行后本组各设备会**自动热重启**，重启后恢复原配置

**注意事项**：
1. 运行脚本前须确保**所有设备连接已关闭**
2. 设备热重启较慢（**5~10 分钟**），非必要不用；命令打错时可用 `undo + 相应命令` 撤销
3. 只清除单个设备：在该设备用户视图输入 `reboot fast`
4. 关闭电源，实验中所作配置也会丢失

## 附录 A：IPv4 与子网速查

### 地址分类

| 类别 | 首字节范围 | 默认掩码 | 用途 |
| :--- | :--- | :--- | :--- |
| A | 1–126 | 255.0.0.0 | 超大型网络（127 为回环保留） |
| B | 128–191 | 255.255.0.0 | 中型/大型网络 |
| C | 192–223 | 255.255.255.0 | 小型网络 |
| D | 224–239 | — | 组播，保留 |
| E | 240–254 | — | 研究测试，保留 |

### 特殊地址

- **网络地址**：主机号全 0，表示网络本身（如 `192.168.1.0`）
- **广播地址**：主机号全 1（如 `192.168.1.255`）
- **回环地址**：`127.0.0.1`，代表本机
- **`0.0.0.0`**：未知网络，用于默认路由

### CIDR 与子网划分

- `192.168.1.1/24` 中，`/24` 表示掩码高 24 位为 1（即 `255.255.255.0`）
- **网段号** = IP 地址与掩码做**逻辑与**运算的结果
- **子网个数** = 2^子网位数 − 2
- **每子网主机数** = 2^主机位数 − 2
- 子网划分可提高地址利用率、减少广播、便于管理，但会有地址浪费（全 0 / 全 1 不可用）

**划分子网示例**：`192.168.10.0/24` 划分 4 个子网、每网 ≥25 台主机
→ 借 3 位，掩码 `255.255.255.224`，可得到 6 个可用子网，取前 4 个即可：

| 子网 | 网络地址 | 可用主机范围 |
| :--- | :--- | :--- |
| 1 | 192.168.10.32 | .33 ~ .62 |
| 2 | 192.168.10.64 | .65 ~ .94 |
| 3 | 192.168.10.96 | .97 ~ .126 |
| 4 | 192.168.10.128 | .129 ~ .158 |

## 附录 B：常用命令行命令速查（Windows）

| 命令 | 作用 | 常用形式 |
| :--- | :--- | :--- |
| `ping` | 测试连通性 | `ping IP`、`ping -t IP`（持续）、`ping -l 200 IP`（指定大小） |
| `tracert` | 跟踪路由路径 | `tracert IP`、`tracert IP -d`（不解析域名，更快） |
| `ipconfig` | 查看网络配置 | `ipconfig`、`ipconfig /all`（完整信息） |
| `netstat` | 查看连接/端口/统计 | `netstat -an`、`netstat -e -s` |
| `arp` | 查看/管理 ARP 缓存 | `arp -a`（显示ARP表）、`arp -d`（删除） |
| `route` | 查看/编辑路由表 | `route print`、`route print 10.*` |

> 注：IPv6 下 ARP 已被 NDP（邻居发现）协议取代。
